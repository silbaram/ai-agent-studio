# 설계

## 목표

게임에 등장하는 요소들의 **밸런스를 기획**하는 스킬과 도구를 만든다. 대상은 아이템(종류·스탯), 강화, 합성, 몹(종류·스탯), 재화와 가격, 그리고 이 요소들 사이의 관계다. 에이전트가 곡선과 예산을 세워 표를 제안하고, 요소 사이의 관계(처치 시간, 버티는 타격 수, 구매까지 걸리는 시간)를 계산으로 확인한다. 모든 수치는 출처(가정·계산·측정)를 달고 단일 원본에 둔다.

게임 개발 과정 전체를 관리하는 도구(일정, 범위 관리, 수명주기, 그래픽 인계)는 만들지 않는다. 2026-11-03에 이 방향으로 다시 정렬했다. 그 전 목표는 "기획부터 완성까지 관리"였다.

## 첫 대상

- 장르: 액션 로그라이크 + 메타 성장형. 시험 프로젝트는 `my-roguelike`(비공개, 로컬)다.
- 엔진: 도구는 엔진 중립 데이터(JSON/CSV)만 다룬다. 게임이 같은 파일을 읽게 하는 것이 엔진 연결이다.

## 범위

| 다룬다 | 다루지 않는다 |
|---|---|
| 공통 스탯과 전투 공식, 요소 간 계산표 | 개발 일정, 태스크, 스펙 관리 |
| 티어·구역별 예산 곡선과 표 단위 제안 | 범위 이탈 차단, 수명주기 단계 강제 |
| 아이템 종류 체계, 아이템 강화, 합성 규칙 | 프로토타입 제작 관리 |
| 몹 원형과 구역별 스탯, 보상 | 그래픽 제작과 인계 |
| 재화 수입과 가격·강화비, 드랍 확률 | 재미 판정 |
| 수치 출처 태그, 단일 원본, 읽기 전용 뷰어 | |

플레이 기록은 밸런스 수치를 실측으로 보정할 때만 쓴다(`[가정]` → `[측정]`).

## 원칙

1. **계산할 수 있는 것은 스크립트로.** 에이전트가 수치를 암산하지 않는다. 처치 시간, 기대 비용, 확률은 도구가 계산하고 결과 파일을 출처로 남긴다.
2. **모든 수치에 출처 태그.** `[가정]` / `[계산: …]` / `[측정: …]`. 에이전트가 제안한 수치는 가정이다. 가정이 남으면 확정 판정 금지. → `skills/numeric-provenance`
3. **곡선에서 표로.** 항목을 하나씩 감으로 정하지 않는다. 티어·구역별 예산 곡선과 원형을 먼저 정하고, 표는 거기서 만든다. 곡선을 벗어난 항목은 의도를 적는다.
4. **요소는 하나의 스탯 모델로 잇는다.** 아이템 점수와 몹 위협도를 따로 매기지 않는다. 같은 스탯과 공식으로 "이 장비로 이 몹을 몇 초에 잡나"를 계산한다.
5. **결정은 사용자가 한다.** 에이전트는 표와 계산을 제안하고, 승인은 사용자가 한다. 재미를 점수로 매기지 않는다.
6. **스킬은 마크다운, 도구는 Python 표준 라이브러리.** bash 의존 없이 Windows에서도 동작하게 한다. 테스트는 `unittest`. 파이썬 코드와 뷰어는 공용 스킬 `studio-data` 한 곳에 두고, 다른 스킬은 절차 문서만 둔다.
7. **가볍게.** 설정 항목을 늘리지 않는다. 공식은 정해진 형태 중에서 고르게 하고, 임의 수식 실행기는 만들지 않는다.
8. **영문 ID, 한국어 설명.** 스킬 이름·태그 키워드·파일명은 영문 규칙, 본문은 한국어.

## 로드맵

| 단계 | 내용 | 상태 |
|---|---|---|
| 0 | 저장소 구조, 수치 출처 태그 규약과 검사기 (`numeric-provenance`) | 완료 |
| 1 | 아이템·영구 강화·적 데이터 단일 원본과 검사기, 읽기 전용 뷰어, 메타 성장 시뮬레이터 (`progression-economy`, `studio-data`) | 1차 완료 |
| B1 | **공통 스탯 모델과 전투 계산.** 스탯 정의, 피해·방어·치명 공식(정해진 형태 중 선택), 구역별 기준 장비의 플레이어. 몹별 처치 시간과 버티는 타격 수를 계산하고 목표 범위를 벗어나면 경고 | 다음 |
| B2 | **예산 곡선과 표 제안.** 티어·구역별 스탯 예산, 아이템 종류(원형)별 예산 배분, 몹 원형. 곡선에서 표 초안을 만들고 곡선 이탈을 검사 | |
| B3 | **아이템 강화와 합성.** 강화 단계별 효과·비용(·성공률), 합성 규칙. 원하는 티어까지의 기대 비용, 합성으로 가치가 불어나는 고리, 도달할 수 없는 아이템을 검사 | 합성 방식 결정 필요 |
| B4 | **재화 흐름.** 구역별 수입(처치 보상·드랍)과 가격·강화비. 구매까지 걸리는 시간, 남는 재화 | |
| B5 | 런 안의 성장(레벨업·빌드 선택)을 B1 모델에 연결, 메타 시뮬레이터의 추상 "힘"을 B1 스탯으로 바꾸기 | |

### 보류 (지우지 않고, 넓히지 않는다)

| 스킬·기능 | 보류 이유 | 다시 쓰는 경우 |
|---|---|---|
| `concept-exploration` | 밸런스 이전 단계(어떤 게임을 만들지)다 | 새 게임의 방향을 정할 때 |
| `playtest-verdict`, 판정 에이전트, 데이터 검사 훅 (`studio.py setup claude`) | 개발 과정 관리 쪽이다 | 밸런스 수치를 플레이 기록으로 보정할 때. 데이터 검사 훅은 밸런스 데이터에도 그대로 쓸 수 있다 |

### 뺀 것

범위 이탈 차단 훅(`scope-guard`), 수명주기 뼈대 연결(spec-kit / OpenSpec), 레벨 설계 체크리스트, 그래픽 인계(`art-handoff`). 조사 기록(`docs/research/`)은 남긴다.
