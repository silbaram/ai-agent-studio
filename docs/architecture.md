# 설계

## 목표

게임 프로젝트를 기획부터 완성까지 AI 에이전트와 함께 관리하되, 개발이 처음 의도에서 벗어나지 않게 한다. 그래픽은 게임성이 완성된 뒤에 입힌다.

## 첫 대상

- 장르: 액션 로그라이크 + 메타 성장형 (확정 전, 방향만 정함)
- 엔진: Godot, Unity, Unreal, Roblox 모두 고려. 그래서 도구는 엔진 중립 데이터(JSON/CSV)만 다룬다. 엔진별 연결은 얇은 어댑터나 안내 문서로 둔다.

## 층 구조

```
[수명주기 뼈대]  기획 → 설계 → 태스크 → 구현 → 검증
                 spec-kit 또는 OpenSpec + superpowers식 실행 규율 (외부 도구, 시험 후 결정)

[게임 설계 층]   컨셉 탐색·반증, 시스템 설계, 레벨, 아이템·경제, 밸런스 측정, 재미 검증 게이트
                 ← 이 저장소가 만든다

[그래픽 층]      도트·메시·VFX 제작과 검수
                 ← silbaram/game-art-skills (기존)
```

일반 수명주기 도구는 기능을 스펙으로 쓰고 구현하는 데 강하지만 재미·레벨·밸런스·아이템을 다루지 않는다. 이 저장소는 그 빈틈만 채우고, 뼈대는 검증된 도구를 쓴다. 근거는 [조사 문서](research/landscape-2026-11.md)를 본다.

## 원칙

1. **기계로 강제할 수 있는 것은 스크립트로.** "하지 마라"는 문장보다 검사기·훅·CI를 우선한다.
2. **모든 수치에 출처 태그.** `[가정]` / `[계산: …]` / `[측정: …]`. 가정이 남으면 확정 판정 금지. → `skills/numeric-provenance`
3. **재미 검증은 증거가 있어야 통과.** 실행 기록, 플레이 기록, 텔레메트리 없이 "재미있다"를 판정하지 않는다. unknown은 실패와 구분한다.
4. **만드는 쪽과 판정하는 쪽을 권한으로 분리.** 판정 역할은 읽기 전용으로 둔다.
5. **스킬은 마크다운, 도구는 Python 표준 라이브러리.** bash 의존 없이 Windows에서도 동작하게 한다. 테스트는 `unittest`.
6. **가볍게.** 단계는 필요한 만큼만 쓴다. 설정 항목을 늘리지 않는다.
7. **영문 ID, 한국어 설명.** 스킬 이름·태그 키워드·파일명은 영문 규칙, 본문은 한국어.
8. **그래픽 유보.** 회색 박스 증거를 인정하고, 마지막에 game-art-skills로 넘길 인계 정보를 만든다.

## 로드맵

| 단계 | 내용 | 상태 |
|---|---|---|
| 0 | 저장소 구조, 조사 기록, 수치 출처 태그 규약과 검사기 | 완료 |
| 1 | 아이템·영구 강화·적 데이터 단일 원본과 검사기, 읽기 전용 데이터 뷰어, 메타 성장 시뮬레이터 | 1차 완료 |
| 1+ | 런 내 모델 보강(누적 체력, 빌드 선택), 플레이 기록으로 모델 보정하는 절차 | |
| 2 | 컨셉 탐색·반증·선택 (abagames 방식 참고) | |
| 3 | 시스템 설계, 레벨 설계(그레이박스 검증 체크리스트, 구간 수치 시트) | |
| 4 | 뼈대 도구 시험(spec-kit vs OpenSpec)과 연결, 재미 검증 게이트, 범위 이탈 차단 훅 | |
| 5 | 그래픽 인계: 완성 게임에서 에셋·효과 재고를 뽑아 game-art-skills 브리프로 변환 | |

## 결정 대기

- 대상 게임의 구체 장르·규모 (현재: 액션 로그라이크 + 메타 성장형 방향)
- 뼈대 도구 선택(spec-kit / OpenSpec)
- 시험용 게임 프로젝트를 별도 저장소로 둘지
- 라이선스
