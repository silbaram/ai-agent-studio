1

게임 폴더에 설치한다

🙋 사람

게임 폴더 안에 스킬 16개를 모두 넣습니다. 필요한 것은 Node.js(설치할 때만)와 Python 3.9 이상입니다.

내-게임/ ├─ .claude/ │ ├─ skills/ ← 스킬 16개 │ ├─ agents/ ← 판정 에이전트 │ └─ settings.json ← 자동 검사 ├─ design/ ← 아이디어·약속서 ├─ data/ ← 게임 숫자 └─ playtests/ ← 플레이 기록
① 스킬 넣기 (Claude Code)
npx skills add silbaram/ai-agent-studio --skill '*' --agent claude-code --copy
② 판정 에이전트와 자동 검사 넣기
python3 .claude/skills/studio-data/scripts/studio.py setup claude .
③ 데이터를 브라우저로 보기 (뷰어)
python3 .claude/skills/studio-data/scripts/studio.py view .

Codex와 Windows는 명령이 조금 다릅니다. README의 설치를 보세요.

아이디어 후보를 걸러 하나를 고른다

🤖 후보 만들기🙋 고르기

에이전트가 후보를 많이 만들고 걸러서 몇 개만 보여 줍니다. 고르는 것은 사람입니다. "가장 재미있어 보이는 것"으로 점수를 매기지 않습니다.

원하는 것 묻기 (5개 이하)한 판 길이, 원하는 느낌, 피할 것…
▼
서로 다른 후보 12개
▼
쉬운 꼼수로 깨 보기가만히 있기, 버튼 하나만 누르기…
▼
겹치는 후보 정리
▼
비교표 3~5개
▼
🙋 하나를 고른다
  • 꼼수 하나로 이기는 후보는 규칙을 하나 바꿔 다시 봅니다. 정말 안 되는 것만 뺍니다.
  • 뺀 후보도 지우지 않고 이유와 함께 남깁니다.
  • 이미 만들고 있는 게임이면 후보를 만들지 않고 3번으로 바로 갑니다.
나
이렇게 말하면 됩니다$concept-exploration으로 혼자 만드는, 한 판이 짧은 카드 게임 아이디어를 찾아줘. 재미 점수로 고르지 말고 구조가 다른 후보를 비교표로 보여줘.

4

만들 것(시스템)을 나누고 순서를 본다

🤖 나누기🧮 순서와 경고

전투, 성장, 상점처럼 필요한 시스템을 나누고, 무엇이 무엇에 기대는지 적습니다. 도구가 만드는 순서를 알려 줍니다.

  • 어떤 약속에도 이어지지 않거나 "안 만들 것"에 걸리는 시스템은 경고가 나옵니다.
  • 무엇부터 만들지, 시험판에 무엇을 넣을지는 사람이 정합니다.
5

그림 없는 시험판을 만든다

🤖 게임 코드🧮 계산과 검사

시험판은 네모와 색만으로 만듭니다. 재미를 확인하는 데 그림은 필요 없습니다. 게임 코드는 평소처럼 에이전트와 만듭니다(이 스킬들이 코드를 대신 짜지는 않습니다).

숫자는 처음부터 data/ 파일 한 곳에 둡니다. 게임도, 밸런스 계산도 같은 파일을 읽습니다.

숫자 옆에는 어디서 왔는지 표시합니다

[가정]일단 정한 값
[계산]도구로 맞춘 값
[결정]사람이 정한 기준
[측정]플레이 기록에서 잰 값
말랑한 숫자단단한 숫자

[가정]이 남아 있으면 "확정"이라고 말하지 못합니다. Claude Code에서는 파일을 고칠 때마다 검사가 자동으로 돕니다. 직접 돌릴 때는 아래 명령입니다.

python3 .claude/skills/studio-data/scripts/studio.py check .
6

직접 해 보고 기록한다

🙋 플레이🤖 기록

재미는 사람이 직접 해 본 기록으로만 정합니다. 결과를 본 뒤 기준을 바꾸면 안 되므로, 기준은 플레이 전에 정합니다.

🙋 플레이 전

  • 몇 명이 몇 판 할지
  • 어디부터 틀렸다고 볼지
  • 화면에 필요한 것이 보이는지

🙋 플레이

  • 사람이 직접 한다
  • 봇이 돌린 판은 봇이라고 표시

🤖 플레이 뒤

  • data/playtests.json에 기록
  • 말한 것과 로그에 있는 것만 적는다
나
이렇게 말하면 됩니다$playtest-verdict로 오늘 플레이한 것 기록해줘. 나 혼자 5판 했고 빌드는 지금 커밋이야. 판정은 studio-judge에게 맡겨서 제안만 보여줘.

판정은 기록만 읽는 심판 에이전트(studio-judge)가 제안하고, 사람이 확정합니다. 심판은 파일을 고칠 수 없습니다(Claude Code).

✅ 맞았다 버팀

잰 값을 [측정]으로 올리고 숫자와 레벨을 다듬습니다. 가설이 모두 버티면 production-handoff로 엔진을 정하고 본 게임으로 넘어갑니다.

❌ 틀렸다 틀림

규칙 하나를 고쳐 다시 시험하거나, 2번으로 돌아가 다른 아이디어를 고릅니다.

❔ 아직 모른다 모름

실패가 아닙니다. 모자란 것을 채워 6번을 다시 합니다.

확정하기 전에 [가정]이 남았는지 막는 검사
python3 .claude/skills/studio-data/scripts/studio.py check . --fail-on-assumed

늘 옆에서: 범위 지키기

🧮 scope-guard🙋 넓힐지 정하기

만들다 보면 처음 약속보다 기능이 늘어납니다. 개발 작업을 OpenSpec(따로 설치하는 외부 도구)으로 나누면, 그 작업이 약속서의 범위 안인지 봅니다. Claude Code에서는 범위를 넓히는 편집 앞에서 사용자에게 묻습니다.

개발 작업
→
약속서의 범위 안?
→
예 → 그대로 진행
아니오 → 🙋 넓힐지 사람이 정한다

OpenSpec을 쓰지 않으면 이 부분만 빠지고 나머지는 그대로 씁니다.

아직 하지 않는 것

엔진별 절차

엔진 프로젝트 만들기와 빌드는 다루지 않습니다. 데이터는 어느 엔진이든 읽을 수 있는 JSON/CSV로 두지만, 엔진별로 확인하지는 않았습니다.

본 게임으로 넘어가기의 검사

가설이 맞은 뒤 엔진을 고르고 본 게임으로 넘어가는 절차는 production-handoff에 문서로만 있습니다. 검사기와 실제 시험은 아직입니다.

그래픽과 사운드

그림을 직접 만들지는 않습니다. 본 게임 화면을 만들기 전에 art-handoff가 화면에서 읽혀야 하는 것과 그릴 것을 정리해 game-art-skills나 사람에게 넘깁니다. 현장 시험은 아직입니다.

말뜻은 쉬운 안내, 설치와 명령은 README, 자세한 규칙은 각 스킬의 SKILL.md에 있습니다. 이 파일은 저장소를 받은 뒤 브라우저로 열어 봅니다.
