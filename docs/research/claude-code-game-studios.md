# Claude Code Game Studios 분석

- 대상: [Donchitos/Claude-Code-Game-Studios](https://github.com/Donchitos/Claude-Code-Game-Studios) (MIT)
- 조사일: 2026-11-02, 얕은 클론 기준. 스타 약 3.2만.
- 방법: 4개 영역(파이프라인, 강제 장치, 에이전트, 레벨·경제·컨셉)을 하위 에이전트가 나눠 읽고 종합했다. 파일·줄 인용은 하위 에이전트 보고에 근거하며 모두 개별 재검증한 것은 아니다. 코드는 실행하지 않았다.

## 한 줄 평가

문서 체인과 질문 방식은 좋지만, 개발 이탈을 기계적으로 막는 장치는 거의 없고 레벨·경제·밸런스는 계산 도구 없이 LLM 판단에 맡긴다.

## 규모

에이전트 49, 스킬 74, 훅 15, 규칙 14, 템플릿 약 60. 스킬 본문 합계 약 2만 줄. 설정 해석 헬퍼 `yaml-helper.sh` 2152줄.

## 잘 만든 부분

- 컨셉 → 시스템 분해 → GDD → (아키텍처·ADR) → 에픽·스토리 → 구현 → 완료 검증의 산출물 체인과 추적 키(GDD 파일명, TR-ID, 스토리 `## Files`와 git 변경 대조).
- 브리프 MVP 항목이 7개를 넘으면 되돌려 보내고 "가장 위험한 것부터" 빌드 순서를 강제.
- `story-done` 판정 순서 BLOCKED > NOT ASSESSED > WITH NOTES > COMPLETE, "코드만 읽고 통과시키지 않기".
- `dev-story` 범위 밖 파일 금지, 보고한 파일이 디스크에 없으면 실패.
- 컨셉 기법: 필러마다 "X와 Y 중 이 필러는 __를 고른다" 설계 테스트, 안티필러, 안마다 최대 리스크.
- `balance-check`는 목표값이 없는 수치를 판정하지 않고, 데이터가 없으면 "NOT ASSESSED"를 정상 결과로 본다.
- 체크포인트 파일(`active.md`)을 세션 시작과 압축 직후 자동 주입.

## 약한 부분

- **차단 장치가 거의 없다.** 훅이 exit 2로 막는 경우는 JSON 손상과 40KB 초과 문서 통독 두 가지뿐. 단계(stage)를 읽는 스킬이 없고 `gate-check`는 스스로 "Never block a user"라고 한다. `story-done`의 BLOCKED도 "Close anyway"로 닫을 수 있다.
- **기본값에서 깊은 흐름이 꺼져 있다.** 기본 rigor=minimal → review=solo라 디렉터 게이트 28종이 하나도 돌지 않는다. 문서는 이를 "Required Gates"라고 불러 모순.
- **수치는 LLM 암산.** 수치 담당 에이전트는 Bash가 막혀 있고 저장소에 `.py`, `.csv`가 없다. 경제 템플릿의 시뮬레이션 결과 칸은 비어 있다.
- **실행 증거와 독립 검토가 없다.** 49개 에이전트 모두 Write/Edit 권한이 있어 읽기 전용 리뷰어가 없다. team-* 오케스트레이션은 실행·캡처 증거를 요구하지 않는다.
- **레벨·경제 단계가 척추에 없다.** 템플릿은 있으나 쓰는 스킬이 없다.
- **비대함과 중복.** 에이전트 정의의 약 33%가 반복 줄. 승인 규약이 원칙 문서·에이전트·자동화 모드에서 서로 다르게 말한다.
- **이식성.** 훅이 bash 전용이라 Git Bash 없는 Windows에서 전부 동작하지 않는다. 시간 초과 시 조용히 통과한다.
- **테스트가 실행 검증이 아니다.** 스킬 spec을 LLM이 읽고 판정하는 방식이고 실행 이력과 CI가 없다.
- **우리 용도와 충돌.** 아트 바이블을 앞 단계에 요구하고, Roblox 지원이 없고, 문서가 영어 전용이다. GDD 섹션 제목을 영어 정규식으로 검사한다.

## 가져올 것 / 버릴 것

| 처리 | 대상 |
|---|---|
| 유지 | 브리프 흐름, 스토리 템플릿 핵심 필드, story-done 판정 순서와 범위 검사, dev-story 경계 규칙, "PASS를 만들어내지 않는다", NOT ASSESSED 순위, 수치의 단일 출처(registry) 개념 |
| 단순화 | 설정 → 키 2개, map-systems → MVP·의존성 표, design-system → 짧은 섹션 몇 개, gate-check → 3단계 |
| 재작성 | 레벨·경제 단계, 훅(Python), 테스트(결정적), 그래픽 유보 규칙 |
| 삭제 | 49개 에이전트 위계, 디렉터 게이트 대부분, TR registry·ADR 버전 스탬프, 스프린트 계획, 효과 맵, 레거시 설정 |

## 우리에게 남긴 교훈

1. "산으로 가지 않게"는 문서 체인만으로는 안 된다. 범위 밖 수정 차단 같은 기계적 장치가 필요하다.
2. 수치에는 출처가 있어야 한다. → `skills/numeric-provenance`
3. 만드는 쪽과 판정하는 쪽을 권한으로 분리해야 한다(읽기 전용 리뷰어).
