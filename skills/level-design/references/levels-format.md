# 레벨 구성 형식

게임 프로젝트의 `data/levels.json` 한 파일에 위협도 예산과 레벨을 둔다. 검사: `python3 .claude/skills/studio-data/scripts/studio.py check .`(적·전투 계산·스탯 예산·재화 흐름 데이터와 함께), 보기: `… view .`.

레벨 구성 파일은 하나만 쓴다. 둘이면 뒤의 파일이 오류다. 단계 범위와 처치 수를 파일을 넘어 세지 않기 때문이다. 최상위에 `levels`나 `threat_budget`이 있어야 이 형식으로 읽는다. 내용이 없는 `levels.json`(빈 파일, `{}`, `[]`, `null`)과 문법이 깨진 `levels.json`은 읽기 오류다. 두 키가 모두 없는 객체, 내용이 있는 최상위 배열, 주석이 있는 JSON은 게임이 자기 형식으로 쓰는 파일일 수 있어 건너뛰고, `check`와 뷰어가 건너뛰었다는 참고 줄을 낸다. 그 파일을 고칠 때는 편집 훅도 알린다. 키를 잘못 적어도 이 줄이 나오므로 그때는 키를 고친다. 게임 파일에 최상위 `levels` 키가 있으면 이 형식으로 검사해 오류가 나므로, 그 파일은 `design/`·`data/`와 프로젝트 폴더 바로 아래가 아닌 곳에 둔다.

```json
{
  "threat_budget": {
    "curve": { "growth": "linear", "base": 90, "rate": 60 },
    "roles": { "room": 1, "elite_room": 1.2, "boss_room": 1 },
    "tolerance": 0.25,
    "provenance": { "kind": "assumed" }
  },
  "levels": [
    {
      "id": "crypt",
      "name": "버려진 지하묘지",
      "combat_stage": "zone_1",
      "intent": "느린 적으로 시작해 궁수로 움직임을 강요한다",
      "encounters": [
        { "id": "crypt_skirmish", "role": "room", "repeat": 5, "enemies": { "slime": 6, "skeleton_archer": 4 } },
        { "id": "crypt_lord", "role": "boss_room", "enemies": { "bone_lord": 1 } }
      ],
      "status": "approved",
      "provenance": { "kind": "assumed" }
    }
  ]
}
```

## `threat_budget`

없으면 위협도만 내고 예산과 비교하지 않는다(`INCOMPLETE`). 아래와 곡선에 없는 키는 오류다(`_`로 시작하는 키와 `note`는 메모로 둔다). 곡선의 기준은 전투 단계의 순서로 정해져 있어 스탯 예산의 `by`를 쓰지 않는다.

| 키 | 필수 | 뜻 |
|---|---|---|
| `curve` | 예 | `{growth, base, rate}`. `linear`: base + rate × (순서 − 1), `exponential`: base × (1 + rate)^(순서 − 1). 순서는 전투 계산의 삭제되지 않은 단계 순서(1부터)다. 단계를 삭제하면 뒤 단계가 당겨져 예산이 바뀐다(경고에 나온다). 끼우거나 맞바꿔도 바뀌므로, 단계 구성이 바뀔 수 있으면 `table`을 쓴다. `table`: `{growth: "table", values: {단계 id: 값}}`. 표에 없는 단계는 오류다 |
| `roles` | 예 | `{역할 이름: 0보다 큰 배수}` |
| `tolerance` | 아니오 | 위협도의 허용 오차. 0 이상 1 미만의 비율(기본 0.2) |
| `kills_tolerance` | 아니오 | 재화 흐름과 비교하는 처치 수의 허용 오차. 0 이상 1 미만의 비율(기본 0.2) |
| `provenance` | 아니오 | 예산의 출처. 곡선의 근거를 `note`에 적는다. 입력 중 하나라도 가정이면 `assumed`다. 입력이 모두 확정이고 다른 데이터에서 계산했으면 `computed`와 `source`, 플레이 기록이면 `measured`와 `source`를 쓴다. 가정이거나 비어 있으면 `--fail-on-assumed`에서 실패한다 |

## `levels`

아래에 없는 키는 오류다(`_`로 시작하는 키는 메모로 둔다).

| 키 | 필수 | 뜻 |
|---|---|---|
| `id` | 예 | 소문자·숫자·밑줄 |
| `name`, `intent`, `note` | 아니오 | 이름, 의도, 메모 |
| `combat_stage` | 아니오 | 이어지는 전투 단계 id. 없으면 레벨 id와 같은 단계 |
| `encounters` | 예 | 조우 배열. 판에서 지나는 순서대로 |
| `status`, `provenance`, `acknowledged` | 아니오 | 다른 데이터와 같다. 경고는 레벨에서 `{코드: {조우나 적 id: 이유}}`로 확인한다. 단계 전체의 경고(`kills_differ`, `enemy_unplaced`, `enemy_not_in_stage`)는 그 단계의 어느 레벨에서든 확인할 수 있다. 어느 레벨에도 걸리지 않는 경고(`kills_not_linked`, `curve_unused_point`)는 아무 레벨에서 확인한다 |

한 전투 단계의 레벨은 한 판에 모두 지나는 것으로 센다. 대체 맵(한 판에 그중 하나만 나옴)은 조우의 `repeat`를 나오는 확률로 나눠 적는다. 셋 중 하나가 나오면 `repeat`는 1/3배다.

스테이지 선택형 게임은 임무마다 레벨을 두고 `table` 곡선으로 비단조 난이도를 적는다. 같은 임무의 어려움 등급은 두 가지로 적는다. 등급마다 기준 장비나 보상이 다르면 **등급을 전투 단계로 나눈다**(`m2_normal`, `m2_hard`). 그 차이가 없고 위협도만 다르면 한 레벨에 등급별 조우를 두고, `roles`에 등급 배수(`hard_room` 1.5)를, `repeat`에 그 등급을 고르는 비율을 적는다. 비율을 나누지 않고 같은 단계의 레벨로 더 넣으면 처치 수가 더해진다. 등급을 나눠도 한 판에 고르는 것은 하나이므로 재화 흐름의 `stages`에는 대표 등급 하나만 적는다. 둘 다 적으면 누적 수입이 두 등급을 모두 지난 값이 된다. 재화 흐름에 없는 등급은 처치 수를 대조하지 않고, 판 전체 위협도는 두 등급을 더한 값이라 읽지 않는다.

## `encounters`

조우 id는 파일 전체에서 겹치지 않는다. 아래에 없는 키는 오류다(`_`로 시작하는 키는 메모로 둔다).

| 키 | 필수 | 뜻 |
|---|---|---|
| `id` | 예 | 소문자·숫자·밑줄 |
| `name`, `intent`, `note` | 아니오 | 이름, 의도, 메모 |
| `role` | 예산이 있으면 예 | `threat_budget.roles`의 역할 |
| `enemies` | 예 | `{적 id: 0보다 큰 수}`. 한 번 만날 때 동시에 나오는 수(평균이면 소수) |
| `repeat` | 아니오 | 한 판에서 만나는 횟수(기본 1, 평균이면 소수) |
| `enemy_repeat` | 아니오 | `{이 조우의 적 id: 0보다 큰 횟수}`. 조우의 `repeat`와 다르게 나오는 적만 적는다. 그 적은 조우가 이어지는 내내 있어야 한다. 일부 횟수에만 나오는 적은 조우를 나눈다. 위협도와 앞 조우 대비가 그 적이 늘 있는 값으로 나오기 때문이다 |
| `provenance` | 아니오 | 레벨과 출처가 다른 조우. 가정이면 `--fail-on-assumed`에서 `레벨.조우`로 걸린다. `kills_differ`의 출처는 조우에 출처가 있으면 그 값을, 없으면 레벨의 값을 적마다 읽는다 |

조우의 크기는 한 규칙으로 통일한다. 곡선은 그 크기에서만 뜻이 있다.

- **방·웨이브**: `enemies`는 한 번 만나는 수, `repeat`는 그런 방을 지나는 횟수.
- **끊임없이 나오는 적**(시간 구간): `enemies`는 화면에 동시에 있는 평균 수, `repeat`는 그 구간에서 무리가 다시 차는 횟수(구간 길이 ÷ 다시 차는 주기). 구간의 누적 수를 `enemies`에 넣으면 위협도가 곡선을 몇 배 넘긴다.
- **보스와 곁의 무리**: 한 조우로 적고 보스만 `enemy_repeat`로 뺀다. 나눠 적으면 보스의 위협도가 곁의 무리 없이 재진다.

```json
{ "id": "z4_press", "name": "3:00~4:00 무리", "role": "swarm", "repeat": 13, "enemies": { "wraith": 10 } },
{ "id": "z4_boss", "role": "boss", "repeat": 10, "enemies": { "rot_queen": 1, "wraith": 7 }, "enemy_repeat": { "rot_queen": 1 } }
```

뒤 조우는 위협도가 여왕 1과 레이스 7의 합이고, 처치는 여왕 1, 레이스 70이다.

## 계산

- **조우의 위협도**: Σ(적 수 × 적의 위협도). 적의 위협도는 적 검사의 값이다. 스탯 예산이 있으면 그 적 원가, 없으면 `threat_weights`로 낸다. `repeat`와 `enemy_repeat`는 곱하지 않는다.
- **앞 조우 대비**: 조우의 위협도 ÷ 같은 레벨의 앞 조우의 위협도.
- **예산**: 곡선 값 × 역할 배수. 범위는 ±`tolerance`다.
- **횟수**: 적마다 `enemy_repeat`, 없으면 조우의 `repeat`.
- **레벨 위협도**: Σ(적 수 × 적의 위협도 × 횟수). 한 레벨에서 만나는 위협의 총량이다. **위협도 합**은 한 단계의 레벨을 더한 값, **판 전체 위협도**는 모든 레벨을 더한 값이다. 앞 단계보다 합이 줄면 참고 줄이 나온다.
- **처치 수**: Σ(적 수 × 횟수). 한 전투 단계의 레벨을 모두 더해 재화 흐름의 `kills`와 비교한다. 재화 흐름의 단계는 `combat_stage`로, 없으면 같은 id로 잇는다. `kills`가 없거나 비어 있으면 비교하지 않는다.
- **처치 시간**: 조우 표는 Σ(적 수 × 전투 계산의 `time_to_kill`), 곧 그 조우를 한 번 치우는 시간이다. 단계 표는 Σ(처치 수 × `time_to_kill`)이고 재화 흐름의 `duration`으로 나눠 비율을 낸다. 단일 대상 기준이라 범위 공격은 들어가지 않는다. 처치 시간을 모르는 적이 있으면 조우 표는 `–`이고, 단계 표는 그 적을 뺀 값에 "이상"을 붙여 실제보다 작다는 것을 밝힌다. 전투 계산에 공격 속도가 없으면 처치 시간 대신 타수(`hits_to_kill`로 같은 계산)와 길이당 타수를 내고 표의 열 이름도 타수로 바뀐다. 재화 흐름의 `time_unit`이 초가 아니면 시간 비율을 내지 않는다. 칸이 모두 비면 참고 줄이 이유를 말한다. 없는 적이 든 조우는 처치 시간을 내지 않고, 조우가 빠진 레벨의 처치 수에는 "(일부)"가 붙는다.
- **평범한 조우의 적 수**: 곡선 값 ÷ 스탯 예산의 적 곡선(`by: "zone"`일 때, 전투 단계의 `zone`으로 읽는다).
- `--table levels`의 끝에 전투 단계별 처치 수를 재화 흐름 `kills`에 옮길 수 있는 JSON으로 낸다. 조우가 빠진 단계는 내지 않는다. 파일에 쓰지 않는다.

## 검사

| 코드 | 수준 | 조건 |
|---|---|---|
| `schema` | 오류 | 형식 위반, 레벨·조우·예산·곡선의 모르는 키, 레벨 구성 파일이 둘 이상 |
| `duplicate_id` | 오류 | 조우 id가 겹침 |
| `unknown_role` | 오류 | `roles`에 없는 역할 |
| `unknown_enemy` | 오류 | 적 데이터에 없는 id |
| `unknown_stage` | 오류 | 전투 계산에 없는 단계. 레벨이 없는 단계를 먼저 오타로 보고 목록으로 보인다. 레벨이 있는 단계는 오타로 단정하지 않고 이름이 비슷한 단계로만 말한다 |
| `curve_missing_point` | 오류 | `table` 곡선에 그 단계가 없음 |
| `curve_not_positive` | 오류 | 그 단계의 곡선 값이 0 이하 |
| `cut_referenced` | 경고 | 삭제된 적이나 단계를 가리킴. 계산에서 뺀다. 삭제된 적은 `kills_differ`로 다시 알리지 않는다 |
| `over_budget`, `under_budget` | 경고 | 위협도가 예산 범위 밖. 삭제된 단계 때문에 순서가 당겨졌으면 메시지에 적는다 |
| `curve_unused_point` | 경고 | `table` 곡선의 값이 가리키는 전투 단계가 없음. 값이 없는 단계만 오타로 추정한다. 다음 단계를 미리 적어 둔 값이면 아무 레벨의 `acknowledged`에 `{"curve_unused_point": {단계 id: 이유}}`로 적는다 |
| `enemy_not_in_stage` | 경고 | 전투 단계에 나오지 않는 적을 놓음. 단계와 적마다 한 줄이고 놓은 조우를 나열한다 |
| `enemy_unplaced` | 경고 | 전투 단계의 적이 어떤 조우에도 없음 |
| `kills_differ` | 경고 | 조우의 처치 수가 재화 흐름과 `kills_tolerance`를 넘게 다름. 양쪽 출처와 고칠 쪽을 말한다. 조우의 출처는 그 적을 놓은 조우에서 읽고, 조우마다 다르면 "섞임"이다. 재화 흐름의 출처는 단계에서, 없으면 `economy`에서 읽는다. 측정값이 앞서고, 측정값이 없으면 조우가 원본이므로 재화 흐름을 옮기라고 말한다 |
| `kills_not_linked` | 경고 | 처치 수가 있는 재화 흐름 단계가 어떤 레벨이나 전투 단계와도 이어지지 않아 맞춰 보지 못함. 일부러 그렇다면 아무 레벨의 `acknowledged`에 `{"kills_not_linked": {재화 흐름 단계 id: 이유}}`로 적는다 |

형식이 틀렸거나 없는 적을 가리키는 조우가 있는 단계, 형식이 틀려 빠진 레벨이 있는 단계는 `enemy_unplaced`, `enemy_not_in_stage`, `kills_differ`를 보지 않는다. 일부만 세어 틀린 경고를 내지 않기 위해서다. 어느 단계인지 알 수 없는 레벨이 있으면 모든 단계에서 보지 않고 `kills_not_linked`도 내지 않는다. 이런 단계는 위협도 합과 처치 시간도 내지 않고, 조우가 빠진 레벨의 레벨 위협도도 내지 않는다. 빠진 레벨이 있거나 조우가 없는 전투 단계가 있으면 판 전체 위협도를 내지 않는다.

미확인(`INCOMPLETE`): 적이나 전투 계산을 함께 읽지 않음, 적 검사를 마치지 못함, 적의 위협도를 내지 못한 조우가 있음, `threat_budget`이 없음, 조우가 없는 전투 단계가 있음, 계산한 조우가 하나도 없음. 재화 흐름은 레벨이 가리키는 데이터가 아니므로 없어도 미확인이 아니다. 대신 "처치 수 대조" 참고 줄이 몇 단계까지 맞춰 봤는지 말한다.

참고 줄은 경고가 아니다. 곡선의 출처가 가정임, 앞 단계보다 위협도 합이 줄어듦, 처치 수 대조 범위를 알린다.
