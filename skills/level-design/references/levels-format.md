# 레벨 구성 형식

게임 프로젝트의 `data/levels.json` 한 파일에 위협도 예산과 레벨을 둔다. 검사: `python3 .claude/skills/studio-data/scripts/studio.py check .`(적·전투 계산·스탯 예산·재화 흐름 데이터와 함께), 보기: `… view .`.

레벨 구성 파일은 하나만 쓴다. 둘이면 뒤의 파일이 오류다. 단계 범위와 처치 수를 파일을 넘어 세지 않기 때문이다. 최상위에 `levels`나 `threat_budget`이 있어야 이 형식으로 읽는다. 내용이 없는 `levels.json`(빈 파일, `{}`, `[]`, `null`, 주석뿐인 파일)과 문법이 깨진 `levels.json`은 읽기 오류다. 이 형식의 키가 있는데 주석이 있어도 읽기 오류다. 두 키가 없는 객체, 내용이 있는 최상위 배열, 두 키가 없고 주석이 있는 JSON은 게임이 자기 형식으로 쓰는 파일일 수 있어 건너뛰고, `check`와 뷰어가 건너뛰었다는 참고 줄을 낸다. 그 파일을 고칠 때는 편집 훅도 알린다. 키를 잘못 적어도 이 줄이 나오므로 그때는 키를 고친다. 게임 파일에 최상위 `levels` 키가 있으면 이 형식으로 검사해 오류가 나므로, 그 파일은 `design/`·`data/`와 프로젝트 폴더 바로 아래가 아닌 곳에 둔다.

```json
{
  "threat_budget": {
    "curve": { "growth": "linear", "base": 90, "rate": 60 },
    "roles": { "room": 1, "elite_room": 1.2, "boss_room": 1 },
    "tolerance": 0.25,
    "provenance": { "kind": "assumed" }
  },
  "levels": [
    {
      "id": "crypt",
      "name": "버려진 지하묘지",
      "combat_stage": "zone_1",
      "intent": "느린 적으로 시작해 궁수로 움직임을 강요한다",
      "encounters": [
        { "id": "crypt_skirmish", "role": "room", "repeat": 5, "enemies": { "slime": 6, "skeleton_archer": 4 } },
        { "id": "crypt_lord", "role": "boss_room", "enemies": { "bone_lord": 1 } }
      ],
      "status": "approved",
      "provenance": { "kind": "assumed" }
    }
  ]
}
```

## `threat_budget`

없으면 위협도만 내고 예산과 비교하지 않는다(`INCOMPLETE`). 아래와 곡선에 없는 키는 오류다(`_`로 시작하는 키와 `note`는 메모로 둔다). 곡선의 기준은 전투 단계의 순서로 정해져 있어 스탯 예산의 `by`를 쓰지 않는다.

| 키 | 필수 | 뜻 |
|---|---|---|
| `curve` | 예 | `{growth, base, rate}`. `linear`: base + rate × (순서 − 1), `exponential`: base × (1 + rate)^(순서 − 1). 순서는 전투 계산의 삭제되지 않은 단계 순서(1부터)다. 단계를 삭제하면 뒤 단계가 당겨져 예산이 바뀐다(경고에 나온다). 끼우거나 맞바꿔도 바뀌므로, 단계 구성이 바뀔 수 있으면 `table`을 쓴다. `table`: `{growth: "table", values: {단계 id: 값}}`. 표에 없는 단계는 오류다 |
| `roles` | 예 | `{역할 이름: 0보다 큰 배수}` |
| `tolerance` | 아니오 | 위협도의 허용 오차. 0 이상 1 미만의 비율(기본 0.2) |
| `kills_tolerance` | 아니오 | 재화 흐름과 비교하는 처치 수의 허용 오차. 0 이상 1 미만의 비율(기본 0.2) |
| `provenance` | 아니오 | 예산의 출처. 곡선의 근거를 `note`에 적는다. 입력 중 하나라도 가정이면 `assumed`다. 입력이 모두 확정이고 다른 데이터에서 계산했으면 `computed`와 `source`, 플레이 기록이면 `measured`와 `source`를 쓴다. 가정이거나 비어 있으면 `--fail-on-assumed`에서 실패한다 |

## `branches`

없어도 된다. 플레이어가 순서를 고르는 전투 단계의 묶음 배열이다. 예: `"branches": [{"stages": ["reed_marsh", "abbey", "shell_coast"], "take": "all"}]`.

| 키 | 필수 | 뜻 |
|---|---|---|
| `stages` | 예 | 전투 계산 순서에서 이어 붙은 단계 둘 이상(변형 단계 제외). 묶음끼리 겹치지 않는다 |
| `take` | 아니오 | `all`(기본, 모두 지나며 순서만 고른다) / `one`(하나만 고른다. 임무의 어려움 등급 등) |

묶은 단계는 이렇게 읽는다.

- 같은 순서를 나눈다. 단계 표의 순서에 `2 (갈래 …)`로 보이고, `linear`·`exponential` 곡선도 같은 순서의 값을 쓴다.
- 앞 단계 대비는 갈래 안에서는 갈래 앞 단계와, 갈래 뒤 단계는 가장 센 갈래와 견준다. 위협도 합이 줄었다는 참고 줄도 같은 단계와 견준다.
- 판 전체 위협도: `all`은 모두 더하고, `one`은 고르는 갈래에 따라 범위(가장 약한 갈래 ~ 가장 센 갈래)로 낸다.
- 레벨을 넘는 쉬는 곳·보상 구간과 강한 조우 연속은 갈래 단계로 들어가거나 나올 때 끊는다.
- 전투 계산과 판 안 성장의 레벨은 단계마다 하나라, 늦게 고른 갈래가 더 높은 레벨로 들어가는 효과는 계산에 없다. 그 차이는 갈래마다 따로 본 단계나 플레이 기록으로 본다.

틀린 묶음은 오류이고 그 묶음은 쓰지 않는다(아래 검사 표).

## `pacing`

없어도 된다. 없으면 표만 내고 경고하지 않는다. 아래에 없는 키는 오류다(`_`로 시작하는 키와 `note`는 메모로 둔다).

```json
"pacing": { "max_rest_load": 8, "max_reward_load": 5, "max_strong_run": 2, "provenance": { "kind": "assumed", "note": "쉬는 곳 사이에 평범한 방 여덟 개는 기획 판단" } }
```

| 키 | 필수 | 뜻 |
|---|---|---|
| `max_rest_load` | 아니오 | 쉬는 곳 사이 부담의 상한(평범한 조우 몇 개 분량). 넘으면 `long_stretch` |
| `max_reward_load` | 아니오 | 보상 사이 부담의 상한. 넘으면 `reward_drought` |
| `max_strong_run` | 아니오 | 강한 조우가 이어지는 횟수의 상한. 넘으면 `strong_run` |
| `strong_at` | 아니오 | 세기가 이 값 이상이면 강한 조우다(기본 1 + `tolerance`, 곧 평범한 조우의 범위 위) |
| `carry_levels` | 아니오 | 쉬는 곳 구간과 강한 조우 연속을 레벨이 끝나도 끊지 않는다(기본 false). 체력이 다음 레벨로 이어지는 게임에 쓴다. 없을 때 레벨을 넘어 상한을 넘는 연속은 참고 줄로 알린다. 층을 넘겨 더한 부담은 곡선에 견준 상대값이라 체력 소모와 같지 않다. 보상 구간은 이 키와 상관없이 판 끝까지 잇는다 |
| `provenance` | 아니오 | 기준의 출처. 위의 수를 적었는데 가정이거나 비어 있으면 `--fail-on-assumed`에서 실패한다 |

## `levels`

아래에 없는 키는 오류다(`_`로 시작하는 키는 메모로 둔다).

| 키 | 필수 | 뜻 |
|---|---|---|
| `id` | 예 | 소문자·숫자·밑줄 |
| `name`, `intent`, `note` | 아니오 | 이름, 의도, 메모 |
| `combat_stage` | 아니오 | 이어지는 전투 단계 id. 없으면 레벨 id와 같은 단계 |
| `greybox` | 아니오 | 그래픽 없이 확인할 항목 배열. 아래 `greybox` 절 |
| `encounters` | 예 | 조우 배열. 판에서 지나는 순서대로 |
| `status`, `provenance`, `acknowledged` | 아니오 | 다른 데이터와 같다. 경고는 레벨에서 `{코드: {대상: 이유}}`로 확인한다. 대상은 경고가 말하는 조우나 적의 id, 단계 id, 구매 id, 구간(`첫 조우~끝 조우`)이다. 단계 전체의 경고(`kills_differ`, `enemy_unplaced`, `enemy_not_in_stage`, `kill_time_over_length`)는 그 단계의 어느 레벨에서든 확인할 수 있다. 어느 레벨에도 걸리지 않는 경고(`kills_not_linked`, `curve_unused_point`)는 아무 레벨에서 확인한다. 값이 있는 경고(구간의 부담, 실패한 값)는 이유에 확인 값을 적어 둔다([studio-data의 확인한 경고](../../studio-data/SKILL.md#실행)). 확인한 `greybox_failed`의 항목에 새 세션을 기록하면 확인을 지우고 다시 본다 |

한 전투 단계의 레벨은 한 판에 모두 지나는 것으로 센다. 대체 맵, 스테이지 선택형, 라운드로 나뉜 게임은 [게임 형태별로 적는 법](game-shapes.md)을 따른다.

## `encounters`

조우 id는 파일 전체에서 겹치지 않는다. 아래에 없는 키는 오류다(`_`로 시작하는 키는 메모로 둔다).

| 키 | 필수 | 뜻 |
|---|---|---|
| `id` | 예 | 소문자·숫자·밑줄 |
| `name`, `intent`, `note` | 아니오 | 이름, 의도, 메모 |
| `role` | 적이 있고 예산이 있으면 예 | `threat_budget.roles`의 역할. 적이 없는 구간의 역할은 이름표라 `roles`에 없어도 되고 예산과 견주지 않는다. `hazard`와 함께 적으면 예산과 견준다 |
| `enemies` | 예 | `{적 id: 0보다 큰 수}`. 한 번 만날 때 동시에 나오는 수(평균이면 소수). 적이 끊임없이 나오는 게임과 끝이 정해진 라운드는 [게임 형태별](game-shapes.md#적이-끊임없이-나오는-게임)로 센다. 적이 없는 구간(쉬는 방, 제단, 상점, 함정, 고요한 시간)은 `{}`로 적는다. 키를 빠뜨리면 오류다 |
| `repeat` | 아니오 | 한 판에서 만나는 횟수(기본 1, 평균이면 소수). 시간 구간은 무리가 다시 차는 횟수다([게임 형태별](game-shapes.md#적이-끊임없이-나오는-게임)) |
| `enemy_repeat` | 아니오 | `{이 조우의 적 id: 0보다 큰 횟수}`. 조우의 `repeat`와 다르게 나오는 적만 적는다. 그 적은 조우가 이어지는 내내 있어야 한다. 일부 횟수에만 나오는 적은 조우를 나눈다. 위협도와 앞 조우 대비가 그 적이 늘 있는 값으로 나오기 때문이다 |
| `at` | 아니오 | 판 시작부터의 시각. 재화 흐름의 구매 `target`과 같은 시계이고 단위는 `time_unit`이다. 없으면 앞 조우가 끝날 때 시작한다 |
| `duration` | 아니오 | 이 조우가 차지하는 **전체** 시간. `repeat`를 곱하지 않는다. 방을 세 번 지나면 세 번을 합친 값을 적는다. `at`만 있고 길이가 없으면 순간(보스 등장, 제단이 열리는 때)이다 |
| `rest` | 아니오 | `true`면 쉬는 곳이다. 체력을 모두 되찾는 것으로 보고 구간을 끊는다. 적이 있는 조우에도 쓴다(지키는 적을 잡고 쉰다). 회복이 없는 게임은 쓰지 않는다([게임 형태별](game-shapes.md#회복이-없는-게임)) |
| `reward` | 아니오 | 공짜로 주는 보상을 글로 적는다. 보상 구간을 끊는다. 적이 있는 조우에도 쓴다(보스 상자). 돈을 내고 사는 구매 시설은 보상이 아니다. 계속 들어오는 보상(레벨업)은 한 자리에서 끊을 수 없어 적지 않는다. 플레이어 행동에 달린 보상은 [게임 형태별](game-shapes.md#플레이어-행동으로만-나오는-적과-보상) |
| `hazard` | 아니오 | 적 없이 드는 소모(함정, 독 지대)를 위협도로 적은 값. 조우의 위협도에 더하고 처치 수에는 넣지 않는다. 평범한 적의 위협도로 정한다. 쥐(위협도 5.4) 한 마리 몫이면 1이 아니라 5.4다 |
| `purchases` | 아니오 | 이 조우에서 일어나는 재화 흐름의 구매 id 배열. 같은 id를 두 번 적지 않는다. 시각이나 단계를 맞춰 본다 |
| `open_for` | 아니오 | 시설이 구매를 받는 시간(0보다 큰 수). `at`, `purchases`와 함께 쓴다. `at: 300`, `open_for: 900`이면 300초에 열려 1200초까지 산다. 판의 시간을 차지하지 않아서 단계를 넘어도 되고, 빈 시간을 메우지 않으며, 뒤 조우의 시각을 밀지 않는다 |
| `provenance` | 아니오 | 레벨과 출처가 다른 조우. 가정이면 `--fail-on-assumed`에서 `레벨.조우`로 걸린다. `kills_differ`의 출처는 조우에 출처가 있으면 그 값을, 없으면 레벨의 값을 적마다 읽는다 |

조우의 크기는 게임 형태마다 한 규칙으로 통일한다(방, 끊임없이 나오는 적, 끝이 정해진 라운드, 보스와 곁의 무리, 갈림길은 [게임 형태별로 적는 법](game-shapes.md)). 형태와 상관없는 규칙:

- **적이 없는 구간**: `enemies`를 `{}`로 적는다. 위협도 0이고 예산과 견주지 않는다. 앞 조우 대비는 이 구간을 건너뛰어 앞 싸움과 견준다. 적이 있는 조우가 하나도 없는 전투 단계는 조우가 없는 단계로 친다.
- **시간이 겹치는 구간**: 같은 시간에 나오는 조우는 `at`을 같게 적는다. 다음 조우는 가장 늦게 끝나는 구간 뒤에 시작한다.
- **열려 있는 시설**: 제단이나 상점이 싸움 동안 열려 있으면 `duration`이 아니라 `at`과 `open_for`로 적는다. `duration`으로 적으면 구간의 끝은 늘리지 않지만 단계를 넘을 때 `time_outside_stage`가 난다.
- **쉬는 곳을 여러 번**: 순서대로 따로 적는다. 한 줄의 `repeat`가 커도 그 자리에서 한 번 끊는다.

## `greybox`

레벨마다 그레이박스에서 확인할 것을 적는다. 아래에 없는 키는 오류다(`_`로 시작하는 키는 메모로 둔다).

```json
"greybox": [
  { "id": "crypt_forge_buy", "check": "대장간에 닿을 때까지 걸린 시간(초)", "encounter": "crypt_forge", "expect": [270, 330], "note": "구역 길이 300초 ±10%" },
  { "id": "citadel_gate_rest", "check": "성문 모닥불에서 체력이 다 차는가", "encounter": "citadel_gate" }
]
```

| 키 | 필수 | 뜻 |
|---|---|---|
| `id` | 예 | 소문자·숫자·밑줄. 파일 전체에서 겹치지 않는다. 플레이 기록이 이 id로 가리킨다 |
| `check` | 예 | 플레이하는 사람이 재거나 답할 수 있는 관찰 |
| `encounter` | 아니오 | 이 레벨의 조우 id |
| `expect` | 아니오 | 기대 범위 [최소, 최대]. 한쪽은 `null`로 비울 수 있다 |
| `note` | 아니오 | 기대 범위의 근거 등 메모 |

판정은 플레이 기록 세션의 `greybox`에서 그 id의 **마지막 기록**(날짜순, 같은 날짜면 세션 id의 순번순)으로 정한다. 값이 있고 `expect`가 있으면 범위로 정한다. 그렇지 않으면 기록의 `passed`를 따른다. 값만 있고 `expect`가 없으면 판정 없음이다. 기록이 없으면 기록 없음이다. 수가 적어 둔 판정보다 앞선다. 통과하지 않은 항목은 `--fail-on-assumed`에서 걸린다. 확인하지 않은 레벨을 확정하지 않기 위해서다.

## 계산

- **조우의 위협도**: Σ(적 수 × 적의 위협도) + `hazard`. 적의 위협도는 적 검사의 값이다. 스탯 예산이 있으면 그 적 원가, 없으면 `threat_weights`로 낸다. `repeat`와 `enemy_repeat`는 곱하지 않는다.
- **앞 조우 대비**: 조우의 위협도 ÷ 같은 레벨의 앞 조우의 위협도. **앞 단계 대비**: 위협도 합 ÷ 값이 있는 앞 단계의 위협도 합.
- **예산**: 곡선 값 × 역할 배수. 범위는 ±`tolerance`다.
- **횟수**: 적마다 `enemy_repeat`, 없으면 조우의 `repeat`.
- **레벨 위협도**: Σ(적 수 × 적의 위협도 × 횟수) + `hazard` × 횟수. 한 레벨에서 만나는 위협의 총량이다. **위협도 합**은 한 단계의 레벨을 더한 값, **판 전체 위협도**는 모든 레벨을 더한 값이다. 앞 단계보다 합이 줄면 참고 줄이 나온다.
- **처치 수**: Σ(적 수 × 횟수). 한 전투 단계의 레벨을 모두 더해 재화 흐름의 `kills`와 비교한다. 재화 흐름의 단계는 `combat_stage`로, 없으면 같은 id로 잇는다. 재화 흐름 단계 여럿이 한 전투 단계를 가리키면 처치 수와 길이를 합쳐 비교하고, 합으로만 맞춰 봤다는 참고 줄이 그 단계들을 말한다. 단계마다 나누는 값은 직접 정한다. `kills`가 없거나 비어 있으면 비교하지 않는다. 재화 흐름에 처치 보상(`kill_reward`)도 처치 수도 없으면(클리어 보상으로 버는 게임) 대조하지 않는다는 참고 줄만 나온다.
- **처치 시간**: 조우 표는 Σ(적 수 × 전투 계산의 `time_to_kill`), 곧 그 조우를 한 번 치우는 시간이다. 단계 표는 Σ(처치 수 × `time_to_kill`)이고 재화 흐름의 `duration`으로 나눠 비율을 낸다. 판 안 성장(`growth.json`)이 있으면 **성장 반영** 열에 같은 비율을 빌드마다 내어 최소~최대로 적고, 값이 다르면 가장 낮은 빌드와 높은 빌드의 이름을 붙인다. 열은 둘이다. **들어설 때 레벨**은 그 단계의 `level_at`이라 단계 안의 레벨업을 넣지 않은 쪽이고, **나갈 때 레벨**은 다음 단계의 `level_at`(빌드가 바꾼 값이 있으면 그 값)이라 단계 안의 레벨업을 모두 넣은 쪽이다. 마지막 단계와, 바로 다음 전투 단계에 `level_at`이 없는 단계는 나갈 때 값이 `–`다. 나갈 때 값도 `level_at`의 출처를 따르는 가정이다. 값을 모르는 적이 있으면 "이상"을 붙이고, 기준 장비 칸에 없는 적은 이름을 적는다. 판 안 성장이 계산하지 않은 단계는 `–`이고 참고 줄이 그 단계를 말한다. 판 안 성장에 오류가 있으면 열을 내지 않고 참고 줄로 알린다. 판 안 성장이 없으면 열이 없다. 단일 대상 기준이라 범위 공격은 들어가지 않는다. 처치 시간을 모르는 적이 있으면 조우 표는 `–`이고, 단계 표는 그 적을 뺀 값에 "이상"을 붙여 실제보다 작다는 것을 밝힌다. 전투 계산에 공격 속도가 없으면 처치 시간 대신 타수(`hits_to_kill`로 같은 계산)와 길이당 타수를 내고 표의 열 이름도 타수로 바뀐다. 길이가 1인 개수 단위(단계·방·판 등)면 길이당 타수는 타수와 같아 내지 않는다. 전투 계산에 변형 단계(`variant_of`)가 있으면 단계 표에 변형 단계 열이 붙고, 같은 처치 수로 낸 변형 단계별 처치 시간(없으면 타수)을 보인다. 재화 흐름의 `time_unit`이 초가 아니면 시간 비율을 내지 않는다. 칸이 비면 참고 줄이 이유를 말한다. 없는 적이 든 조우는 처치 시간을 내지 않고, 조우가 빠진 레벨의 처치 수에는 "(일부)"가 붙는다.
- **세기**: 조우의 위협도 ÷ 그 단계의 곡선 값. 역할 배수를 곱하지 않아서 평범한 조우가 1이다. 세기가 `strong_at` 이상이면 강한 조우다.
- **부담**: 조우의 위협도 × 횟수 ÷ 그 단계의 곡선 값. 곧 평범한 조우 몇 개 분량이고, 횟수는 레벨 위협도와 같이 적마다 센다. 단계마다 곡선으로 나누므로 레벨을 넘어 더할 수 있다.
- **만나는 차례**: 레벨의 조우를 모두 시각을 알면 시각 순서로, 하나라도 모르면 목록 순서로 읽는다. 시간을 나누는 싸움은 한 묶음으로 보고, 적 없는 조우는 같은 시각이면 싸움 앞에 놓는다.
- **구간**: `rest`나 `reward`로 끊은 조우의 묶음. 표시가 있는 조우는 자기 부담까지 넣고 끊는다. 묶음에 표시가 있으면 묶음 전체를 넣고 끊는다. 싸움 묶음 도중의 적 없는 표시도 그 묶음 뒤에 끊는다. 쉬는 곳 구간은 표시가 없으면 레벨 끝에서 끊고, `carry_levels`면 판 끝에서 끊는다. 보상 구간은 판 끝에서 끊는다. 마지막 표시 뒤의 꼬리도 구간이다. 길이는 적 없는 조우로 끊으면 그 시작까지이고, 적이 있는 조우로 끊으면 그 끝까지다. 시간을 차지하지 않는 시설과 순간은 구간을 시작하지 않는다. 표시도 상한도 없는 종류의 구간은 표에 내지 않는다. 곡선이 없거나 위협도를 모르는 조우가 있으면 부담은 `–`다. 일부만 더한 값을 내지 않는다.
- **길이당 부담**: 부담 ÷ `duration`. 시간을 나누는 묶음은 묶음의 값(부담 합 ÷ 묶음의 시간)이라 행끼리 견줄 수 있다. 구간은 구간의 부담 ÷ 길이다. 무리가 다시 차는 주기가 구간마다 다르면 이 값이 튄다.
- **강한 조우 연속**: 강한 조우가 이어지는 횟수. `repeat`까지 세고, 강하지 않은 조우와 쉬는 곳에서 끊는다. 시간을 나누는 묶음은 모두 강해야 강하다. 쉬는 곳이 아닌 적 없는 순간은 숨 돌릴 틈이 없어 끊지 않는다. 횟수가 1보다 작은 조우는 없는 판이 있어 끊지 않는다. 끊임없이 나오는 게임은 무리가 다시 찬 횟수다. 두 번 이상 이어질 때만 낸다.
- **시각**: 판의 시계다. 단계의 첫 레벨은 재화 흐름의 단계 시작에서 출발하고, 재화 흐름이 없으면 앞 레벨이 끝날 때 시작한다. 레벨은 전투 단계의 순서로 지난다. 재화 흐름에 없는 단계(대표가 아닌 등급)는 판의 어디인지 몰라서 `at`을 적은 조우만 시각을 안다. 순간도 시계를 그 시각까지 옮긴다. 시계는 뒤로 가지 않아서 겹치는 구간이나 앞선 순간은 옮기지 않는다. `at`도 `duration`도 없는 조우를 지나면 `at`을 다시 만날 때까지 시각을 모른다.
- **평범한 조우의 적 수**: 곡선 값 ÷ 스탯 예산의 적 곡선(`by: "zone"`일 때, 전투 단계의 `zone`으로 읽는다).
- `--table levels`의 끝에 전투 단계별 처치 수를 재화 흐름 `kills`에 옮길 수 있는 JSON으로 낸다. 조우가 빠진 단계는 내지 않는다. 재화 흐름을 읽었는데 거기 없는 단계에는 `(재화 흐름에 없음)`이 붙는다. 파일에 쓰지 않는다.

| `curve_not_positive` | 오류 | 그 단계의 곡선 값이 0 이하 |
| `unknown_encounter` | 오류 | `greybox`의 `encounter`가 이 레벨의 조우가 아님 |
| `unknown_purchase` | 오류 | `purchases`의 구매가 재화 흐름에 없음. 적혀 있는데 재화 흐름의 오류로 시점을 계산하지 못한 구매는 "시점을 모르는 구매" 참고 줄로 알린다 |
| `cut_referenced` | 경고 | 삭제된 적이나 단계, 구매를 가리킴. 계산에서 뺀다. 삭제된 적은 `kills_differ`로 다시 알리지 않는다 |
| `over_budget`, `under_budget` | 경고 | 위협도가 예산 범위 밖. 삭제된 단계 때문에 순서가 당겨졌으면 메시지에 적는다(그때는 적이 아니라 곡선을 본다). 역할은 그 조우의 쓰임에 맞춘다. 쓰임이 달라졌으면 역할을 바꾸고, 쓰임이 그대로인데 의도한 크기면 이유를 `acknowledged`에 적는다. 경고를 없애려고 역할을 바꾸지 않는다. 스탯 예산의 `over_budget`은 적 하나의 원가를, 이 경고는 조우 하나의 합을 잰다. 이름만 같고 다른 값이다 |
| `curve_unused_point` | 경고 | `table` 곡선의 값이 가리키는 전투 단계가 없음. 값이 없는 단계만 오타로 추정한다. 다음 단계를 미리 적어 둔 값이면 아무 레벨의 `acknowledged`에 `{"curve_unused_point": {단계 id: 이유}}`로 적는다 |
| `enemy_not_in_stage` | 경고 | 전투 단계에 나오지 않는 적을 놓음. 단계와 적마다 한 줄이고 놓은 조우를 나열한다. 앞 구역의 적이 **모두** 계속 나오면 전투 단계에 `zone_rule: "up_to"`를, **일부만** 이어지면 단계의 `enemies` 목록을 적는다. 적이 그 구역에서 끝나는 게임에 `up_to`를 쓰면 끝난 적까지 세어 `enemy_unplaced`가 난다. 플레이어 행동으로만 나오는 적은 [게임 형태별](game-shapes.md#플레이어-행동으로만-나오는-적과-보상) |
| `enemy_unplaced` | 경고 | 전투 단계의 적이 어떤 조우에도 없음. 앞 구역에서 끝난 적이면 단계의 `enemies` 목록으로 뺀다. 조우 밖에서만 나오는 적이면 그 단계의 레벨 하나의 `acknowledged`에 이유를 적는다 |
| `kill_time_over_length` | 경고 | 단계 표의 처치 시간 ÷ 길이가 1배를 넘음(처치 시간에 "이상"이 붙어도). 비율이 없으면(길이를 모름, 초가 아님) 보지 않는다. 처치 시간을 모르는 적을 빼고 낸 하한이 1배 아래면 경고 대신 참고 줄이 나온다(그 적을 전투 계산의 그 단계에 넣으면 잰다). 성장이 없는 빌드(회색 상자)는 그대로 버티지 못한다는 뜻이다. 단일 대상 기준이라 범위 공격·관통·판 안 성장이 메울 수 있다. 메우면 그 단계의 아무 레벨에서 `{"kill_time_over_length": "범위 무기가 무리를 쓸어 담는다"}`처럼 무엇이 메우는지 확인한다. 판 안 성장이 있으면 경고 문장에 들어설 때와 나갈 때 성장 반영 값이 붙고, 들어설 때 일부 빌드만 1배를 넘으면 그 빌드를 적는다(하한이면 "이상"). 경고의 조건에는 쓰지 않는다(빌드 가정에 판정을 맡기지 않는다). 성장이 일부만 메우면 그 값으로 남는 배수를 이유에 적는다("성장 반영 1.4배, 남는 0.4배는 범위 무기"). 플레이 기록이 반대로 말하면(그 단계를 통과한 판이 적거나 처치 속도가 모자람) 확인하지 않는다. 메울 것이 없으면 고칠 후보(조우 수, 다시 차는 주기, 기준 장비)마다 전·후 표를 보여 주고 사용자가 고른다 |
| `kills_differ` | 경고 | 조우의 처치 수가 재화 흐름과 `kills_tolerance`를 넘게 다름. 양쪽 출처와 고칠 쪽을 말한다. 조우의 출처는 그 적을 놓은 조우에서 읽고, 조우마다 다르면 "섞임"이다. 재화 흐름의 출처는 단계에서, 없으면 `economy`에서 읽는다. 측정값이 앞서고, 측정값이 없으면 조우가 원본이므로 재화 흐름을 옮기라고 말한다 |
| `kills_not_linked` | 경고 | 처치 수가 있는 재화 흐름 단계가 어떤 레벨이나 전투 단계와도 이어지지 않아 맞춰 보지 못함. 재화 흐름 단계에 `combat_stage`를 적거나 전투 단계와 같은 id로 둔다. 일부러 그렇다면 아무 레벨의 `acknowledged`에 `{"kills_not_linked": {재화 흐름 단계 id: 이유}}`로 적는다 |
| `greybox_failed` | 경고 | 그레이박스 확인의 마지막 기록이 실패. 레벨을 고치거나, 기대가 틀렸다면 근거와 함께 범위를 고친다. 다음 빌드에서 고치기로 했으면 레벨에서 `{"greybox_failed": {항목 id: 이유}}`로 확인한다. 문자열 한 줄로 확인하면 `schema` 오류이고 어떤 실패도 덮지 않는다 |
| `long_stretch` | 경고 | 쉬는 곳 사이 구간의 부담이 `max_rest_load`를 넘음. 조우를 줄이거나 표시를 옮긴다. 상한을 올려 없애지 않는다. 의도한 구간이면 구간이 시작하는 레벨에서 `{"long_stretch": {"첫 조우~끝 조우": 이유}}`로 확인한다. 이름에 괄호의 레벨 범위는 넣지 않는다. 경고 문장이 옮길 값을 말한다. 구간의 끝이 바뀌면 확인이 풀린다. 확인한 경고 줄에 값이 나온다 |
| `reward_drought` | 경고 | 보상 사이 구간의 부담이 `max_reward_load`를 넘음. 확인은 `long_stretch`와 같다 |
| `strong_run` | 경고 | 강한 조우가 `max_strong_run`을 넘게 이어짐. 사이에 약한 조우나 쉬는 곳을 넣는다. 한 조우의 횟수면 횟수를 줄이거나 조우를 나눠 사이에 약한 조우를 넣는다. 보스 앞 시험처럼 일부러 잇는 곳이면 확인한다. 확인은 `long_stretch`와 같다 |
| `time_gap` | 경고 | 단계의 시간 중 어떤 조우도 차지하지 않는 때가 있음. 단계의 앞뒤도 본다. 적이 없는 구간도 조우로 적어 메운다. 순간과 싸움에 겹치는 적 없는 조우는 시간을 메우지 않는다. 순간만 있는 단계는 길이를 적지 않은 것이라 보지 않는다. 레벨에서 `{"time_gap": {단계 id: 이유}}`로 확인한다 |
| `time_outside_stage` | 경고 | 조우의 시각이 재화 흐름의 단계 시작과 끝을 벗어남. 벗어난 조우를 말한다. 시각이나 재화 흐름의 `duration`을 맞춘다(단계 길이의 원본은 재화 흐름). 레벨에서 `{"time_outside_stage": {단계 id: 이유}}`로 확인한다 |
| `purchase_off_span` | 경고 | 조우에 이은 구매가 재화 흐름에서 그 조우의 시각(`open_for`가 있으면 열린 시간) 밖에 일어남. 메시지가 돈이 먼저 모이는지, 늦으면 그 까닭(돈, `after`, 앞 구매, 단계 끝)을 말한다. 상점이 열리기 전에 돈이 모이면 재화 흐름 구매의 `after`에 그 시각을 수로 적는다. 그때도 열려 있는 시설이면 `open_for`를 적는다. 조우의 시각을 모르면 단계로 본다. `purchase_timing`이 `stage_end`면 단계 끝은 다음 단계의 시작이라 다음 단계의 조우도 맞는다. 레벨에서 `{"purchase_off_span": {구매 id: 이유}}`로 확인한다 |

형식이 틀렸거나 없는 적을 가리키는 조우가 있는 단계, 형식이 틀려 빠진 레벨이 있는 단계는 `enemy_unplaced`, `enemy_not_in_stage`, `kills_differ`를 보지 않는다. 일부만 세어 틀린 경고를 내지 않기 위해서다. 어느 단계인지 알 수 없는 레벨이 있으면 모든 단계에서 보지 않고 `kills_not_linked`도 내지 않는다. 이런 단계는 위협도 합과 처치 시간도 내지 않고, 조우가 빠진 레벨의 레벨 위협도와 구간의 부담도 내지 않으며 시각을 맞춰 보지 않는다. 빠진 시간이 어디인지 몰라 그 단계의 조우는 `at`을 적은 것만 시각을 안다. 구매는 시각을 모르는 조우라면 단계로 맞춰 본다. `carry_levels`일 때 빠진 레벨이 있으면 모든 구간의 부담을 내지 않고 강한 조우 연속은 레벨 안에서만 본다. 빠진 레벨이 있거나 조우가 없는 전투 단계가 있으면 판 전체 위협도를 내지 않는다.

미확인(`INCOMPLETE`): 적이나 전투 계산을 함께 읽지 않음, 적 검사를 마치지 못함, 적의 위협도를 내지 못한 조우가 있음, `threat_budget`이 없음, 조우가 없는 전투 단계가 있음, 계산한 조우가 하나도 없음, 조우의 `purchases`가 있는데 재화 흐름을 읽지 못함. 그 밖에는 재화 흐름이 없어도 미확인이 아니다. 대신 "처치 수 대조" 참고 줄이 몇 단계까지 맞춰 봤는지 말한다.

참고 줄은 경고가 아니다. 곡선과 페이싱 기준의 출처가 가정임, 앞 단계보다 위협도 합이 줄어듦, 처치 수·시각·구매를 어디까지 맞춰 봤는지, 시간이 겹치는 조우, 구간을 끊지 않은 표시, 어떤 경고도 덮지 않은 `acknowledged`(코드나 대상의 오타, 이미 사라진 경고, 잘못된 자리. 자리가 틀렸으면 줄이 적을 곳을 말하고, 재화 흐름 구매에 적은 `purchase_off_span`처럼 레벨 구성이 내는 경고는 레벨에 적는다), 그레이박스 확인의 판정별 수를 알린다. 구매 대조의 수는 맞춰 본 수이고 어긋난 수는 따로 적는다. 시각이나 구매를 적지 않은 게임에는 해당 줄이 나오지 않는다.
