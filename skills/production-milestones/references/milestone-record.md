# 이정표 기록 (`design/production.md` 끝)

[production-milestones](../SKILL.md)의 결정을 [본 게임 넘어가기 기록](../../production-handoff/references/production-record.md) 끝에 이어 쓴다. 아래 틀을 복사해 채운다. 절의 이름은 바꾸지 않는다. 숫자에는 출처 표시를 붙인다([numeric-provenance](../../numeric-provenance/SKILL.md#태그)). 사용자가 정한 것은 `[결정: 사용자 날짜]`다.

검사기가 이 절의 형식을 보지 않는다. 칸을 비워 두지 말고, 모르면 `[?]`라고 적는다.

## 틀

```markdown
## 이정표

되돌아간 횟수: 0

### 알파

| 조건 | 결과 | 근거 |
|---|---|---|
| MVP 시스템이 본 게임에 있다 | 통과 / 실패 / [?] | 아래 표 |
| 버틴 가설의 판정이 지금 데이터의 것이다 | 통과 / 실패 / [?] | check --fail-on-assumed의 플레이 기록 gate 줄 그대로 |
| 틀림으로 확정된 가설이 없다 | 통과 / 실패 / [?] | 같은 출력 |

| MVP 시스템 | 만든 곳 |
|---|---|
| <시스템 id> | <OpenSpec 변경 이름이나 코드 경로, 못 찾으면 [?]> |

결과: 진행 | 되돌아가기 | 그만두기 [결정: 사용자 YYYY-MM-DD]

### 콘텐츠 계획

| 종류 | 데이터 파일 | 알파 때 수 | 계획한 수 | 근거 |
|---|---|---|---|---|
| 카드 | data/cards.json | 18 [계산: check] | 40 [결정: 사용자 YYYY-MM-DD] | <브리프 범위, 한 판 길이> |

### 콘텐츠 묶음

| 날짜 | 더하거나 바꾼 것 | 데이터 지문 | 낡은 판정 | 회귀 결과 | 처리 |
|---|---|---|---|---|---|
| YYYY-MM-DD | 카드 6장(<id 목록>) | <check의 버팀으로 판정할 때 적을 데이터 지문> | <가설 id 목록, 없으면 없음> | <회귀 파일 경로> | 이어 감 / 다시 플레이(<세션 id>) [결정: 사용자 YYYY-MM-DD] |

### 베타

콘텐츠 동결: YYYY-MM-DD [결정: 사용자 YYYY-MM-DD]
남은 [가정] 숫자: <check의 데이터 파일 gate 줄 그대로. 다 정했으면 없음>

| 다듬기 | 어디서 나왔나 | 규칙 그대로 확인 |
|---|---|---|
| <고친 것> | <검사 줄, 세션 메모, 사용자의 말> | <같은 시드 봇 결과가 같음 / 숫자를 바꿔 낡은 판정을 풀었음(묶음 표의 날짜)> |

다른 사람의 플레이: <사람 수 [결정: 사용자 YYYY-MM-DD], 세션 id, 관찰과 수치를 나눈 것. 설계자 혼자면 "설계자 혼자, 한계">

### 출시 후보

출시 목표: 무료 공개 | 판매 [결정: 사용자 YYYY-MM-DD]

| 줄 | 결과 | 근거 |
|---|---|---|
| 판정 | 통과 / 실패 / [?] | <명령과 결과> |

결과: 출시 | 되돌아가기 | 그만두기 [결정: 사용자 YYYY-MM-DD]
출시 빌드: <game_build 이름, 태그>
```

표의 줄은 [출시 게이트](release-gate.md)의 줄 이름을 그대로 쓴다. 판매면 '판매할 때 더하는 것'의 줄도 넣는다.
