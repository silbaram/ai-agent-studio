# 그림에 넘길 것 기록 (`design/art-handoff.md`)

[art-handoff](../SKILL.md)의 결과를 한 파일에 남긴다. 아래 틀을 복사해 채운다. 절의 이름은 바꾸지 않는다. `design/` 아래 md라 Claude Code의 편집 훅이 숫자 출처를 검사한다. 숫자는 되도록 적지 않고(개수 대신 id 목록), 적으면 출처 표시를 붙인다([numeric-provenance](../../numeric-provenance/SKILL.md#태그)).

검사기가 이 파일의 형식을 보지 않는다. 칸을 비워 두지 말고, 모르면 "확인하지 못함"이라고 적는다.

## 틀

```markdown
# 그림에 넘길 것: <컨셉 id>

## 읽혀야 하는 것

| id | 뜻 | 묶음 | 놓이는 곳 | 언제 보여야 하나 | 지금 단서 | 나온 곳 | 기대는 가설 |
|---|---|---|---|---|---|---|---|
| <항목 id, 예: danger_floor> | <뜻, 예: 곧 피해를 주는 바닥> | <묶음, 예: hazard> | <위치와 바탕, 예: 전장 바닥 위> | <예: 피해가 나기 전> | <예: 빨간 테두리만(색뿐)> | <예: 가설 `<id>`의 말 "위험한 곳" / design/systems.json의 함정 규칙> | <예: `<id>`, `<id>_main`. 없으면 없음> |

## 그릴 것

| 종류 | 데이터 | 화면에 나오는 곳 | 함께 쓰는 그림 | 비고 |
|---|---|---|---|---|
| <예: 아이템 아이콘> | <예: data/items.json `items[].id`> | <예: 인벤토리, 상점> | <예: 티어마다 같은 테두리> | <예: 데이터의 안 쓰는 항목 표시와 그 값> |
| <예: 경고 표시> | <데이터 밖: 어느 규칙> | <예: 바닥 위> | <없음> | <예: 읽혀야 하는 것의 hazard 묶음> |

## 그림 방향을 언제 정하나

다시 확인 전 | 다시 확인 뒤 [결정: 사용자 YYYY-MM-DD]
까닭: <내용>
넘긴 곳: 읽혀야 하는 것: <art-direction / 사람 / 아직>, 그릴 것: <asset-sourcing / 사람 / 아직>

## 정한 색과 단서

<다시 확인 전에 정했을 때만. game-art-skills를 쓰면 art/direction.json 경로. 쓰지 않으면 항목 id마다 정한 색과 단서와 [결정: 사용자 YYYY-MM-DD]. 다시 확인 뒤면 해당 없음>

## 바뀐 이력

<바꿀 때마다 한 줄: 날짜, 무엇이 바뀌었나, 기대는 가설, 다시 확인할지 사용자 결정. 없으면 없음>
```

## 칸의 뜻

| 칸 | 뜻 |
|---|---|
| id | 영문 소문자와 밑줄. 그림 쪽에서도 같은 id를 쓴다 |
| 묶음 | 서로 구분해야 하는 항목끼리 같은 이름. 다른 묶음끼리는 같은 색이어도 된다 |
| 놓이는 곳 | 화면의 위치와 그 아래 바탕(어두운 판, 밝은 카드 면). 그림 쪽이 대비를 볼 배경을 고르는 근거다 |
| 언제 보여야 하나 | 플레이어가 그 정보로 고르거나 대답하는 때. 그때 가려지면 안 된다 |
| 지금 단서 | 시험판 화면에서 지금 구분되는 방법. 색만으로 구분되면 그렇다고 적는다 |
| 나온 곳 | 가설의 말(말 인용 표), `design/systems.json`의 규칙, 시험판 화면 중 어디서 나왔나 |
| 기대는 가설 | 이 읽힘에 판정이 기대는 가설 id. `_main`은 7단계에서 더한 뒤 함께 적는다. 없으면 없음 |
| 그릴 것의 데이터 | 파일 경로와 배열 경로. id를 하나씩 옮겨 적지 않아도 되고, 데이터 밖의 것은 어느 규칙에서 나왔는지 |
| 정한 색과 단서 | 7단계 화면이 읽을 곳. 다시 확인 전 길에서 그림 쪽 파일이 없을 때 여기에 적는다 |
| 바뀐 이력 | 앞의 줄은 지우지 않는다. 바뀐 뒤의 순서는 [그림이 바뀌었을 때](after-art-change.md) |
