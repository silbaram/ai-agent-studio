# 구조 축과 변이

후보를 테마가 아니라 구조로 펼치고 비교하기 위한 축이다. 각 후보의 `signature`에 축 이름과 값을 적는다. 아래 값은 출발점이며, 맞지 않으면 새 값을 짧은 영문으로 만든다. 같은 의미에는 같은 값을 써야 검사기가 겹침을 찾는다.

## 축

| 축 | 질문 | 값 예시 |
|---|---|---|
| `decision` | 몇 초마다 다시 내리는 핵심 선택은? | `position`(어디에 설까), `timing`(언제 할까), `allocation`(무엇에 쓸까), `route`(어느 길로 갈까), `build`(무엇을 조합할까), `gamble`(걸까 말까), `deduction`(무엇이 숨어 있을까) |
| `information` | 결정에 필요한 정보가 얼마나 보이나? | `full`, `partial`(일부만, 예고 있음), `hidden`(추론 필요) |
| `commitment` | 한 선택을 되돌릴 수 있나? | `reversible`, `costly`(되돌리면 손해), `permanent` |
| `risk_reward` | 위험과 보상이 어떻게 묶였나? | `none`, `proximity`(가까이 갈수록 보상), `exposure`(오래 노출될수록 보상), `wager`(자원을 걸기), `greed`(머물수록 보상·위험 증가) |
| `space` | 어디서 움직이나? | `arena`(고정 화면), `lane`(한 방향 진행), `rooms`(방 연결), `open`, `grid` |
| `pressure` | 무엇이 플레이어를 밀어붙이나? | `enemies`, `timer`, `resource_drain`(자원이 줄어듦), `escalation`(점점 거세짐), `opponent` |
| `progression` | 무엇이 쌓이나? | `in_run`(한 판 안), `meta`(판 사이), `both`, `none` |

`decision`, `information`, `commitment`, `risk_reward`는 반드시 적는다. 나머지는 해당되면 적는다(최소 4축).

축 이름은 위 표의 이름을 그대로 쓴다. 이름이 다르면 다른 후보와 비교되지 않아 겹침 검사가 조용히 빠진다. 그래서 검사기는 필수 4축이 없으면 오류(`signature_missing_axis`), 표에 없는 축 이름은 경고(`unknown_axis`)로 알린다. 정말 새 축이 필요하면 `constraints.extra_axes`에 이름을 적는다.

## 제약으로 고정된 축

사용자 제약 때문에 모든 후보가 같은 값을 가지는 축은 탐색 대상이 아니다. 예를 들어 "판 안 빌드 + 판 사이 성장"이 제약이면 모든 후보의 `progression`이 `both`다. 이런 축은 `constraints.fixed_axes`에 적는다.

```json
"constraints": { "fixed_axes": { "progression": "both" } }
```

- 검사기는 고정 축을 겹침(`near_duplicate`)·쏠림(`axis_collapse`) 비교에서 뺀다. signature에 적어도 되고 빼도 된다.
- 후보가 고정 값과 다른 값을 적으면 제약 위반일 수 있어 `fixed_axis_mismatch`로 알린다.
- 비교할 축(고정 축 제외)은 여전히 4개 이상이어야 한다.

## 범위 나누기

12개를 만들 때 예를 들어 이렇게 칸을 미리 정한다.

- `decision`이 서로 다른 값 4가지 이상
- `information`의 세 값이 모두 한 번 이상
- `risk_reward`가 `none`인 안은 2개 이하
- 사용자가 준 장르 경계 안에서, 장르 관례와 다른 축 값을 가진 안을 2개 이상

장르 경계가 "액션 로그라이크"라면 `space`·`pressure`는 장르가 정해 주는 경우가 많다. 그럴수록 `decision`·`information`·`risk_reward`에서 넓게 벌린다.

## 6개로 짧게 할 때

- `decision`이 서로 다른 값 4가지 이상
- `information`의 값 2가지 이상
- `risk_reward`가 `none`인 안은 1개 이하
- 장르 관례와 다른 축 값을 가진 안 1개 이상
- 변이(6단계)는 생략해도 된다. 생략했으면 보고에 적는다.
- 6개를 모두 제시해도 된다(7단계의 "3~5개"는 12개 기준이다).

## 변이 연산

약하지만 유망한 후보는 **하나만** 바꾼다. 무엇이 달라질지 예상을 `notes`에 적는다.

| 연산 | 예 |
|---|---|
| 정보 구조 바꾸기 | 적 공격을 모두 보여 주던 것 → 다음 공격만 예고 |
| 확약 바꾸기 | 언제든 바꾸던 무기 → 방에 들어가면 고정 |
| 위험-보상 결합 걸기 | 처치 보상 고정 → 피격 직전 회피 시 보상 2배 |
| 자원 하나를 두 용도로 | 체력 = 탄약 |
| 공간 위상 바꾸기 | 넓은 방 → 좁은 통로가 이어진 방 |
| 시간 축 넣기 | 무한히 머물 수 있던 방 → 머물수록 적 강화 |

하지 않는 것: 업그레이드 트리, 상점, 스토리, 연출, 아이템 수 늘리기로 약한 결정을 감추는 것.

## 멈출 때

아래 중 둘 이상이면 탐색을 멈추고 후보를 제시한다.

- 새 후보가 기존 `signature`와 대부분 겹친다
- 변이가 결정을 늘리지 않고 규칙만 늘린다
- 사용자가 준 범위 안의 의미 있는 칸을 이미 덮었다
- 남은 불확실성이 말로는 풀리지 않고 실제로 만들어 봐야 풀린다
