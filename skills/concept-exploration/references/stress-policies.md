# 단순 전략으로 반증하기

"재미있나?"는 말로 판정할 수 없다. 대신 **이 컨셉이 주장하는 결정이 실제로 의미가 있는지**를 단순한 전략으로 공격해 본다.

## 단순 전략

조작 방식에 해당하는 것만 쓴다.

| policy | 행동 |
|---|---|
| `idle` | 아무것도 안 한다 |
| `spam` | 같은 버튼(공격, 대시)을 계속 누른다 |
| `kite` | 항상 적에게서 멀어지며 공격한다 |
| `rush` | 항상 가장 가까운 적에게 돌진한다 |
| `corner` | 한 구석·안전 지대에 머문다 |
| `safe_only` | 위험한 보상은 절대 잡지 않는다 |
| `greedy` | 보이는 보상을 무조건 잡는다 |
| `one_build` | 매 판 같은 조합만 고른다 |
| `random` | 무작위로 선택한다 |

## 결과 기록

| result | 뜻 |
|---|---|
| `dominates` | 단순 전략이 의도한 숙련 플레이보다 낫거나 같다 → 주장한 결정이 무의미하다 |
| `competitive` | 단순 전략도 꽤 통하지만 숙련 플레이가 앞선다 |
| `loses` | 단순 전략이 분명히 진다 |
| `unknown` | 말로는 판단할 수 없다. 만들어 봐야 안다 |

`unknown`이 아니면 `evidence`에 근거를 적는다. 근거는 규칙에서 따라 나오는 추론이나 실제 관찰이어야 한다. "재미없을 것 같다"는 근거가 아니다. 근거가 없으면 `unknown`으로 둔다.

## 핵심 결정 확인

반증과 별도로, 서로 다른 선택이 더 나은 상황이 **두 가지 이상** 존재하는지 직접 만들어 본다. 예: "적이 둘일 때는 돌진이 낫고, 셋 이상일 때는 거리 두기가 낫다." 만들 수 없으면 결정이 하나로 무너진 것이다. `risk`에 적는다.

## 탈락(hard_reject) 기준

아래처럼 **핵심 루프가 성립하지 않음이 증명된 경우에만** `hard_reject`를 적고 `status`를 `cut`으로 바꾼다.

| type | 뜻 |
|---|---|
| `unreachable_goal` | 목표에 도달할 수 없다 |
| `forced_failure` | 무엇을 해도 실패한다 |
| `dominant_simple_policy` | 단순 전략이 관련 상황 전부에서 이긴다 |
| `no_recurring_decision` | 반복해서 내릴 의미 있는 선택이 없다 |
| `contradiction` | 규칙이 서로 모순되어 루프를 정의할 수 없다 |
| `constraint_violation` | 사용자가 정한 제약(입력, 기간, 규모)을 어긴다 |

탈락 사유가 아닌 것: 낯설다, 그림이 심심하다, 설명하기 어렵다, 수치 조정이 필요해 보인다, 위험하다.

## 보고 원칙

- `unknown`을 실패처럼 말하지 않는다.
- 단순 전략이 "통한다"(`competitive`)와 "지배한다"(`dominates`)를 섞지 않는다.
- 사람이 플레이해서 본 것은 언제·누가·어떤 빌드로 봤는지와 함께 적는다. 사용자의 선호와 관찰을 구분한다.
