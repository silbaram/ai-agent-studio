# 시험판을 키워 갈 때

[production-handoff](../SKILL.md) 5단계에서 사용자가 "키워 가기"를 골랐을 때의 순서. 시험판이 이미 고른 엔진으로 되어 있고, 구조를 그대로 써도 된다고 사용자가 정한 경우만이다. 결과는 `design/production.md`의 '시험판' 절에 적는다([기록 틀](production-record.md)).

## 순서

1. **원본을 남겨 둔다.** 기록(데이터의 설명, 가설의 `test`, 리포트)이 시험판 폴더의 경로를 가리키면 시험판 폴더를 원본으로 그대로 두고, 새 폴더(예: `game/`)로 복사해 거기서 키운다. 원본을 옮기면 기록의 경로가 끊긴다. 데이터를 상대 경로로 읽으면 같은 깊이의 폴더에 둔다. 가리키는 기록이 없으면 시험판을 다른 폴더(예: `archive/prototype-<빌드 지문>/`)로 복사하고 시험판 폴더에서 키워도 된다. 어느 쪽이든 원본은 건드리지 않는다. 지난 판정의 근거다. 본 게임 코드는 원본을 가리키지 않는다(격리 확인은 SKILL.md 5단계).
2. **옮기는 동안 규칙과 숫자를 바꾸지 않는다.** 이때 바꾸는 것은 구조뿐이다: 규칙·상태와 화면을 나누고, 판 로그·봇·분석을 개발용 빌드 기능으로 묶는다. 시험판이 이미 나뉘어 있으면 그대로 둔다.
3. **동일성을 확인한다.** 같은 데이터, 같은 시드로 같은 봇 명령을 원본과 새 빌드에서 돌려 두 결과 파일을 남긴다. 가설의 `test`가 쓰는 지표(예: 봇끼리의 차이, 이긴 전투 수)를 두 파일에서 비교한다. 같으면 바꾸기 시작한다. 다르면 무엇이 달라졌는지 찾기 전에는 바꾸지 않는다.
4. 시드나 봇이 없어 동일성 확인을 할 수 없으면 첫 사람 플레이 세션의 그레이박스 확인 항목으로 대신 보고, 대신했다는 것을 기록에 적는다. 같다고 확인한 것이 아니다.
5. 새 빌드의 판 로그가 시험판 세션에 없는 빌드 이름을 남기는지 본다(SKILL.md 7단계의 `builds`).

## 지키는 것

- 봇 결과는 사람 플레이 기록이 아니다. 동일성 확인은 결과 파일로 남기고 판정의 세션으로 쓰지 않는다. 플레이 기록에 남기려면 `simulated: true`로 적는다(판정에서 빠진다).
- 시험용 수치와 짧은 판 시간 같은 시험용 설정은 동일성 확인이 끝난 뒤에 본 게임 기준으로 바꾼다. 바꾸면 빌드 이름이 바뀐다.
