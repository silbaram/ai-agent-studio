# 본 게임 넘어가기 기록 (`design/production.md`)

[production-handoff](../SKILL.md)의 결정을 한 파일에 남긴다. 아래 틀을 복사해 채운다. 절의 이름은 바꾸지 않는다. 숫자에는 출처 표시를 붙인다([numeric-provenance](../../numeric-provenance/SKILL.md#태그)). 사용자가 정한 것은 `[결정: 사용자 날짜]`, 에이전트가 어림한 것은 `[가정]`이다.

검사기가 이 파일의 형식을 보지 않는다. 대신 칸을 비워 두지 말고, 모르면 "확인하지 못함"이라고 적는다.

넘어가기 판정이 "진행"이면, 그 뒤의 이정표(알파, 베타, 출시 후보)는 [이정표 기록](../../production-milestones/references/milestone-record.md)의 틀로 이 파일 끝에 이어 쓴다.

## 틀

```markdown

## 엔진

### 필수 조건

| id | 조건 | 어디서 나왔나 |
|---|---|---|
| web_export | 브라우저에서 돌아간다 | 브리프 constraints.platform |

| <엔진 A> | <버전> | 통과(문서): <근거> | 통과(시험): <근거> | 통과(시험판): <세션 id나 판 로그 경로> | 낮음: <근거> | |
| <엔진 B> | <버전> | 실패: <근거> | 통과(문서): <근거> | 확인하지 못함 | 확인하지 못함 | web_export 실패 |

주관적 이유(필수 조건이 아니다): <예: 사용자가 이 언어를 써 봤다>

### 엔진 시험

과제: data/*.json을 고치지 않고 읽어 <핵심 루프 하나>를 돌린다. 다 됐다의 뜻: <내용>

| 엔진 | 걸린 시간 | 막힌 곳 | 배포 크기 | 화면 없이 돌았나 |
|---|---|---|---|---|
| <엔진 A> | 3시간 [측정: <작업 기록 경로>] | <없음 또는 내용> | 확인하지 못함 | 예 |

### 위험 목록

| 엔진 | 위험 | 미리 보이는 신호 | 할 일 | 어디서 나왔나 |
|---|---|---|---|---|
| <엔진 A> | <내용> | <본 게임을 만들며 볼 수 있는 일> | <다시 엔진 시험, 되돌아가기 등> | 엔진 시험의 막힌 곳 |

### 고른 엔진

<엔진 이름> <정확한 버전. 엔진 없이면 "엔진 버전 없음"과 빌드 도구·언어의 정확한 버전> [결정: 사용자 YYYY-MM-DD]
버전을 고정한 파일: <엔진 프로젝트 파일 경로, 엔진 없이면 프로젝트 파일과 lock 파일 경로, 또는 고정할 수 없음과 까닭>
추천과 다르게 골랐으면 그 이유: <내용>

## 시험판

이유: <내용>
시험판 보관 위치: <경로. 키워 가기면 원본으로 남긴 폴더(제자리에 둔 시험판 폴더나 원본 복사본)>
(키워 가기일 때) 본 게임 코드 폴더: <경로>
(키워 가기일 때) 동일성 확인: <봇 명령과 시드> / 원본 결과 파일 <경로> / 새 빌드 결과 파일 <경로> / 비교한 지표와 두 값 / 같음 | 다름, 또는 대신 본 그레이박스 항목

| 원래 가설 | 다시 확인할 가설 | 본 게임 빌드(`game_build`) | 표본 | 판정 |
|---|---|---|---|---|
| <가설 id> | <가설 id>_main | <시험판 세션에 없는 이름, 예: main-<지문>> | 1명 4판 [결정: 사용자 YYYY-MM-DD]. 시험판 4판 묶음 3개: 버팀 3, 틀림 0, 모름 0 | 아직 |

## 넘어가기 판정

| 조건 | 결과 | 근거 |
|---|---|---|
| data/playtests.json gate 줄에 모름으로 둠 밖의 가설이 없다 | 통과 | check . --fail-on-assumed 결과 (YYYY-MM-DD) |

```

## 칸의 뜻

| 칸 | 뜻 |
|---|---|
| 필수 조건의 `id` | 후보 표의 열 이름으로 쓴다. 영문 소문자와 밑줄 |
| 어디서 나왔나 | 브리프의 제약, 가설, 시스템 설계, 단일 원본 규칙 중 무엇에서 나온 조건인가. 출처가 없는 조건은 필수 조건이 아니다 |
| 후보의 통과·실패 | 조건마다 `통과(문서)`, `통과(시험)`, `통과(시험판)`, 실패와 근거(문서 링크, 엔진 시험 결과, 시험판의 세션 id나 파일 경로). 확인하지 못했으면 "확인하지 못함"이고 통과로 보지 않는다 |
| 탈락 사유 | 실패한 조건 id. 하나라도 실패한 후보는 고르지 않는다 |
| 지식 위험 | 낮음·중간·높음과 근거, 또는 확인하지 못함. 기준은 [엔진 시험](engine-trial.md#지식-위험). 탈락 사유가 아니다 |
| 엔진 시험의 걸린 시간 | 실제로 잰 값이면 작업 기록을 출처로 `[측정: …]`, 어림이면 `[가정]` |
| 위험 목록 | 시험한 후보마다. 기준은 [엔진 시험](engine-trial.md#위험-목록) |
| 고른 엔진 | 사용자가 고른 엔진과 정확한 버전. "최신"처럼 적지 않는다 |
| 시험판 처리 | 버리고 새로(기본)나 키워 가기 |
| 동일성 확인 | 키워 가기일 때 원본과 새 빌드의 같은 봇 결과 파일 두 개와 비교 결과. 순서는 [시험판을 키워 갈 때](grow-prototype.md) |
| 격리 확인 | 본 게임 코드 폴더에서 '시험판 보관 위치'를 찾은 명령과 결과. 찾은 줄이 있으면 고칠 때까지 진행하지 않는다 |
| 키워 간 직후 빌드와 가르는 것 | [SKILL.md](../SKILL.md#7-본-게임-빌드에서-가설을-다시-확인한다)의 7단계 |
| 가설 없이 만드는 MVP 시스템 | 재미를 플레이로 시험하지 않고 본 게임으로 가져가는 시스템(가설이 닿지 않거나, 모름으로 둔 가설에만 닿는 시스템). 까닭은 `design/systems.json`의 확인에 있고 여기에는 옮겨 적는다. 기준은 [SKILL.md](../SKILL.md#6-가져갈-것과-버릴-것을-적는다)의 6단계 |
| 다시 확인할 가설 | 브리프에 더한 `_main` 가설. 본 게임 빌드 칸은 `builds`에 적은 이름이다. 판정은 `data/playtests.json`에 있고 여기에는 결과만 옮긴다. 더하지 않았으면(다시 확인할 변화 없음) 표 대신 까닭과 사용자 결정을 적는다. 기준은 [SKILL.md](../SKILL.md#7-본-게임-빌드에서-가설을-다시-확인한다)의 7단계 |
| 넘어가기 판정의 결과 | 진행, 되돌아가기, 그만두기 중 하나. 조건 중 "확인하지 못함"이 있으면 진행으로 적지 않는다 |
| 되돌아간 횟수 | 되돌아가기를 고를 때마다 하나씩 더한다 |
| 되돌아간 길 | 되돌아가기를 고를 때마다 한 줄을 더하고 앞의 줄은 지우지 않는다. 다시 확인에서 틀린 뒤 규칙을 바꿨으면 적을 것은 [본 게임 단계에서 규칙을 바꿀 때](rule-change.md#기록) |
