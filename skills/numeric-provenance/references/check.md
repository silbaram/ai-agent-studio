# 출처 태그 검사

`provenance`(기획 문서 md)와 `check`(컨셉 브리프의 판정 기준 문장)가 태그를 어떻게 읽는지 적는다. 태그를 다는 규칙은 [SKILL.md](../SKILL.md#규칙)에 있다.

## 검사 내용

**본문 수치**

- 검사기는 '숫자 + 단위'(초, %, 배, 개, 명, 건 등)마다 뒤따르는 태그가 있는지 보고, 없으면 경고한다. 단위가 없는 숫자는 찾지 못하는 추정 검사라 오류로 막지 않는다.
- 태그는 수치 바로 뒤, 같은 문장 안, 다음 수치 전에 있어야 그 수치를 통과시킨다. 다음 문장의 태그나 수치를 감싼 괄호가 닫힌 뒤의 태그(`(판 끝 30초 전은 빈칸) 공격 강화만 센다 [가정]`)는 통과시키지 않는다. 한 줄의 태그 하나가 같은 줄의 다른 수치를 통과시키지 않는다(`5분 [가정], 3판 + 2명 [가정]`이면 `3판`을 경고).
- 소수점, 파일 이름의 점, 영문 줄임말(`e.g.`)은 문장 끝으로 보지 않는다.
- 범위(`4~9%`)와 가운뎃점으로 이은 목록(`0.5·1·2배`)은 수치 하나로 보고 뒤의 태그 하나로 통과한다. 쉼표로 가른 값은 따로 센다.
- 순서를 말하는 수(`5판째`, `3번째`)는 수치로 보지 않는다. 태그 안의 숫자는 출처 설명으로 보고 검사하지 않는다.
- 경고는 앞 5개를 보이고 나머지는 `외 N개`로 알린다. `--json`의 `values`에 전부 있다.

**컨셉 브리프의 판정 기준 문장**(가설의 `claim`, `failure_signal`, `test`와 `success_criteria`)

- 위 규칙에 더해 단위 없는 소수와 부호 붙은 수(`상관 0.2`, `-0.2`, `+10`)도 수치로 본다. 부호는 값에 들어간다(`+3초`).
- `--fail-on-assumed`는 `[가정]`이 남았거나 태그 없는 수치가 있는 판정 기준 문장을 실패로 본다. 게이트 줄에 남은 값이 `test(가정: 60초, 3개; 태그 없음: 6판)`처럼 보인다.
- `check`는 브리프의 `[계산]`·`[측정]` 출처도 `--check-paths`처럼 확인한다. 경로처럼 보이는 출처는 게임 프로젝트 폴더 기준으로 파일이 있어야 하고, `data/playtests.json#세션 id`면 그 세션이 기록에 있어야 한다. 없으면 오류다.
